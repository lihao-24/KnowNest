# MVP 产品与交互设计

## 设计目标

第一版做一个面向河南省出分后正式志愿辅助筛选的 AI 问答助手。它应该像 ChatGPT 一样自然对话，但比普通聊天更有结构：用户每问一轮，系统都要沉淀考生画像、候选志愿、数据来源和风险点。

产品重点不是“炫酷 AI”，而是帮助家庭在填报志愿前看清：

- 还缺哪些关键信息。
- 哪些学校/专业/计划类型值得看。
- 哪些选择有明显风险。
- 哪些结论有官方数据依据。
- 哪些只是经验判断，需要再核验。

## 目标用户

第一阶段面向家庭内部使用：

- 考生本人。
- 家长。
- 帮忙整理资料和做判断的家庭成员。

默认用户不是招生专家，因此界面和回答要避免术语堆砌。专业术语可以出现，但必须配合简短解释。

## 信息架构

推荐三栏布局：

```text
左侧：会话列表
中间：聊天问答区
右侧：当前总结区
```

当前 UI 基准文件为 `designs/mvp-ui.pen`，包含登录页和主页/志愿问答工作台两张画板。后续前端实现应按该文件的布局、信息密度、状态标签和克制工作台风格落地。

### 左侧会话列表

用途：

- 新建会话。
- 查看历史会话。
- 根据考生或主题区分会话。

MVP 字段：

- 会话标题。
- 更新时间。
- 简短状态，例如“资料未全”“已生成候选”“待核验”。

后续再考虑搜索、归档和标签。

### 中间聊天问答区

用途：

- 用户输入问题。
- 助手追问信息。
- 助手解释志愿规则、推荐候选和风险。

输入区建议：

- 支持多行输入。
- 支持快捷提示，例如“生成冲稳保方案”“解释这个专业风险”“对比这两个学校”。
- 不在第一版做文件上传，数据导入走后台或维护脚本。

回答卡片建议：

- 普通回答：自然语言。
- 候选推荐：自然语言 + 可保存候选项。
- 数据引用：折叠展示，不把正文塞满。
- 风险提示：用标签或短句，不用夸张警告样式。

### 右侧当前总结区

右侧是降低幻觉和减少对话丢失的关键区域，不是装饰。

MVP 分区：

1. 考生画像
   - 河南固定。
   - 分数。
   - 位次。
   - 科类或选科。
   - 国家专项资格。
   - 地域偏好。
   - 专业兴趣和排斥项。
   - 家庭资源。
   - 核心诉求。

2. 缺失信息
   - 系统还需要什么才能完整推荐。
   - 缺少硬信息时，不允许生成完整冲稳保。

3. 候选清单
   - 冲、稳、保分组。
   - 学校、专业或专业组、计划类型、城市。
   - 风险标签。
   - 收藏状态。

4. 数据来源
   - 近三年录取/投档数据。
   - 当年招生计划。
   - 招生章程。
   - 方法论或上游参考。

5. 待核验事项
   - 需要用户去官方系统或招生章程确认的内容。
   - 例如资格、体检、单科、学费、校区、调剂规则。

## 核心用户流程

### 流程一：首次咨询

1. 用户登录。
2. 创建新会话。
3. 用户输入自然语言，例如“河南物理类 580 分，想稳一点，能不能帮我看看”。（用户口语可能说"理科"，系统在画像层做"理科→物理类"归一化，对外展示仍用官方口径"物理类"。）
4. 系统提取画像。
5. 缺少位次、诉求、国家专项资格等关键信息时，助手只追问，不生成完整推荐。
6. 右侧同步显示已知信息和缺失信息。

### 流程二：完整推荐

触发条件：

- 分数。
- 位次。
- 科类或选科。
- 核心诉求。
- 是否考虑国家专项计划。

流程：

1. 规则层查询近三年本科批和国家专项计划数据。
2. 根据资格和偏好过滤。
3. 生成冲稳保候选。
4. 检索相关招生计划、章程和方法论资料。
5. LLM 用直白但克制的风格解释。
6. 右侧候选清单和来源同步更新。

### 流程三：候选对比

用户可以问：

- “A 和 B 哪个更适合？”
- “这个专业是不是坑？”
- “国家专项值得报吗？”
- “如果想考公，哪个更合适？”

系统应：

- 优先基于已保存候选和数据来源回答。
- 对无法确认的数据明确说资料不足。
- 给出下一步核验清单。

### 流程四：保存志愿篮

用户可以把候选项保存到志愿篮。

MVP 保存内容：

- 学校。
- 专业或专业组。
- 批次。
- 计划类型。
- 冲稳保标签。
- 推荐理由。
- 风险标签。
- 来源摘要。
- 用户备注。

第一版不需要生成最终志愿表，但要为后续导出做准备。

## 助手回答原则

### 风格

采用“克制直白”的张雪峰式表达：

- 敢说风险。
- 不绕弯。
- 少鸡汤。
- 讲人话。
- 不羞辱用户。
- 不绝对化承诺。

### 结构

当信息不全：

```text
先说明现在不能完整判断。
指出缺少哪些硬信息。
最多追问 2-3 个关键问题。
```

当信息足够：

```text
先给总体判断。
再给冲稳保候选。
每个候选都说明依据和风险。
最后给官方核验清单。
```

### 禁止

- 编造具体分数线、位次、计划数。
- 用未核验资料生成录取结论。
- 把方法论建议说成官方事实。
- 输出“稳上”“一定录”“绝对别报”等无边界判断。
- 为了像张雪峰而过度攻击用户或家庭。

## 状态设计

### 数据未导入

如果结构化招生数据还没导入，系统只能回答：

- 志愿规则解释。
- 数据准备建议。
- 方法论咨询。

不能生成真实冲稳保。

### 资料不足

如果候选学校缺招生计划或章程，回答应标记：

```text
当前只能基于近三年位次做初筛，缺少当年招生计划或章程，不能下最终判断。
```

### 无结果

如果按硬条件过滤后没有候选：

- 说明是哪些条件导致范围过窄。
- 建议用户调整地域、专业、计划类型或冲稳保目标。
- 不要硬编候选。

## 后续 Pencil 设计重点

当前已完成第一版 Pencil 设计：`designs/mvp-ui.pen`。

后续迭代时优先补充或调整三类状态：

1. 登录后空会话页。
2. 问答进行中，右侧显示画像和缺失信息。
3. 已生成候选，右侧显示冲稳保、来源和风险。

视觉方向：

- 工作台式，不做营销落地页。
- 信息密度适中，适合长时间筛志愿。
- 用清晰标签表达风险和数据等级。
- 卡片半径保持克制，避免花哨。
- 颜色服务于状态区分，不做单一高饱和主题。
