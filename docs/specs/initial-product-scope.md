# 初始产品范围

## 目标

创建一个只服务河南省高考志愿填报的个人 AI 问答助手。产品第一阶段优先服务家庭内部使用，重点帮助考生和家长完成信息收集、志愿方向筛选、专业风险理解和候选方案对比。

## 非目标

- 不做全国通用志愿平台。
- 不替代河南省官方志愿填报系统。
- 不承诺录取结果。
- 不把大模型回答当成官方事实。
- 不使用未经标注来源和年份的数据直接计算录取概率。

## 用户体验方向

界面形态参考 ChatGPT Web：

- 左侧或顶部管理会话
- 主区域为对话流
- 输入框支持继续追问
- 助手主动要求补全省份、科类/选科、分数、位次、兴趣、地域、家庭资源和就业诉求
- 关键建议以卡片或表格呈现，便于收藏到志愿篮

表达风格参考张雪峰式咨询：

- 先问清楚再建议
- 直白指出风险
- 用就业、家庭资源和地域现实倒推
- 避免只给情绪价值

但需要保留边界：

- 不能使用羞辱式、歧视性或绝对化表达
- 不能把经验判断包装成官方结论
- 每个涉及录取、分数、位次的建议都要说明数据依据

## 第一阶段建议能力

1. 考生画像采集
   - 河南省固定
   - 科类或选科
   - 分数、位次、批次线
   - 专业兴趣和明确排斥项
   - 城市偏好和不能接受的地域
   - 家庭资源、预算和就业目标

2. 志愿问答
   - 解释河南志愿规则
   - 解释学校、专业、城市取舍
   - 解释专业就业风险
   - 对比多个学校或专业

3. 候选推荐
   - 基于近年位次和当年计划做初筛
   - 输出冲、稳、保
   - 给出风险标签和核验清单

4. 志愿篮
   - 收藏学校/专业
   - 标记冲稳保
   - 记录推荐理由、风险和来源
   - 后续支持导出

## 第一阶段数据优先级

1. 河南省教育考试院公开数据
2. 高校招生网和招生章程
3. 阳光高考等官方平台
4. 学校官网、学院官网、就业质量报告
5. 经验规则和公开就业趋势

第一版可以先人工整理 CSV/JSON，再接自动导入。

## 待确认问题

- 技术栈是否直接采用 Next.js + TypeScript。
- 本地数据先用 SQLite、JSON/CSV，还是直接 PostgreSQL。
- 是否需要账号登录；如果只家庭使用，第一版可暂不做复杂用户体系。
- 域名暴露采用现有反向代理、Docker Compose，还是和现有本地项目共用部署方式。
- AI Provider 使用哪个 OpenAI-compatible 服务。
